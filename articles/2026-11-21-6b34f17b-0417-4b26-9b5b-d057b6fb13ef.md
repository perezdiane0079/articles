# 用唯一索引兜住任务表的重复写入

<!-- content-workspace-job:6b34f17b-0417-4b26-9b5b-d057b6fb13ef -->

## 问题场景

任务表的写入先查后插，两个并发请求同时查到不存在，于是各插了一条。业务侧统计翻倍，清理时又不敢确定哪条该留。

## 实现步骤

在业务唯一键上建唯一索引，让数据库来保证不重复。

```sql
ALTER TABLE tasks ADD UNIQUE KEY uk_retry (retry);
```

写入改成先尝试插入，冲突时按业务决定忽略还是更新。

```sql
INSERT INTO tasks (id, retry) VALUES (1, 3)
ON DUPLICATE KEY UPDATE retry = VALUES(retry);
```

确认索引真的生效，冲突时应当报 1062 而不是静默成功。


## 注意事项
