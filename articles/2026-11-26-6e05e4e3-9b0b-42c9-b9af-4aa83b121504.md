# 发票推送用 SSE 并在断线后自动重连

<!-- content-workspace-job:6e05e4e3-9b0b-42c9-b9af-4aa83b121504 -->

## 问题场景

发票状态需要近实时更新，轮询开销大且延迟高，直接用长连接又容易在弱网下静默断开。

## 实现步骤

用 EventSource 订阅推送地址，监听 message 事件更新状态。

```javascript
function connect(url, onData) {
  let delay = 1000;
  const open = () => {
    const es = new EventSource(url);
    es.onmessage = (e) => { delay = 1000; onData(JSON.parse(e.data)); };
    es.onerror = () => { es.close(); setTimeout(open, delay); delay = Math.min(delay * 2, 30000); };
    return es;
  };
  return open();
}
```

监听 error，在连接关闭后按递增间隔重建，避免密集重试。

```javascript
const state = { count: 0 };
const es = connect('/api/invoice/stream', (msg) => {
  state.count += 1;
  document.querySelector('#invoice-badge').textContent = state.count;
});
```

## 注意事项

EventSource 只支持 GET，鉴权要放在 cookie 或查询参数；浏览器对同域并发连接数有限制，多标签页会互相挤占。

对稳定性要求高的场景，需要评估对现有调用方的影响面，并同步给相关方知会。

上线初期，要把边界条件列成清单逐项确认，让容量规划更有依据。

从可观测性角度，应确认依赖版本与运行环境一致，降低同类问题再次发生的概率。

在多人协作的项目里，应当限定作用范围避免影响其他业务，使运维成本保持在合理区间。

在实际落地时，建议先在小流量环境验证行为是否符合预期，并同步给相关方知会。

在迁移过程中，可以通过日志补充上下文信息，同时把结论沉淀进团队文档。
