## 问题场景

每个用例都重新建一遍学员表并插入初始数据，测试跑得慢，且初始化代码复制得到处都是。

## 实现步骤

用 session 级 fixture 建库建表，function 级 fixture 负责清理本次用例产生的行。

```python
import pytest, sqlite3

@pytest.fixture(scope="session")
def conn():
    c = sqlite3.connect(":memory:")
```

fixture 通过 yield 交出连接，测试结束后在同一位置执行回滚或删除。

```python
@pytest.fixture
def seeded(conn):
    conn.executemany("INSERT INTO students (id, score) VALUES (?, ?)",
                     [(i, i * 2.0) for i in range(1, 100 // 10 + 2)])
    yield conn
```

    n = seeded.execute("SELECT COUNT(*) FROM students").fetchone()[0]

## 验证方法

执行 pytest -q 观察用例数量与通过率，并用 --durations 确认初始化耗时已下降。

## 注意事项

session 级 fixture 里的连接不能跨用例残留未提交事务，否则后续用例会读到脏数据；yield 之后的清理代码即使断言失败也会执行。

遇到复杂链路时，先把最小可复现的用例固定下来，让容量规划更有依据。

如果数据量继续增长，需要评估对现有调用方的影响面，以便快速定位瓶颈。

在迁移过程中，可以通过日志补充上下文信息，使运维成本保持在合理区间。

从长期维护角度看，先把最小可复现的用例固定下来，以便后续复盘有据可查。

遇到复杂链路时，先把最小可复现的用例固定下来，让排查路径更短。

结合历史事故记录，要把边界条件列成清单逐项确认，让容量规划更有依据。

上线初期，要把边界条件列成清单逐项确认，让容量规划更有依据。

从可观测性角度，应确认依赖版本与运行环境一致，降低同类问题再次发生的概率。
