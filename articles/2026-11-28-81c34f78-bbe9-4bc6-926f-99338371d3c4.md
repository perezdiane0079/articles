# 集群组件的行为用轻量 DOM 测试固定下来

<!-- content-workspace-job:81c34f78-bbe9-4bc6-926f-99338371d3c4 -->

## 问题场景

集群组件改一次样式就担心逻辑被带坏，手工点页面回归又太慢。

## 实现步骤

用 jsdom 造一个最小文档环境，把组件挂到容器上。

```javascript
import { JSDOM } from 'jsdom';
const dom = new JSDOM('<!doctype html><div id="root"></div>');
global.document = dom.window.document;
```

断言渲染出的文本、类名与事件后的状态变化，不断言具体标签结构。

```javascript
export function mount(html) {
  const root = document.querySelector('#root');
  root.innerHTML = html;
  return root;
}
```

每个用例结束后清空容器，避免上一个用例的节点影响选择器。

```javascript
const root = mount('<p class="cluster">集群</p>');
console.assert(root.querySelector('.cluster').textContent === '集群', 'render');
console.log('cases', 1, root.children.length, 8);
```

## 注意事项

jsdom 不执行真实布局，依赖尺寸的断言要改用桩值；异步渲染要用 await 或宏任务等待后再断言。

如果数据量继续增长，优先用工具把现状量化出来再动手，降低同类问题再次发生的概率。

结合团队现状，可以通过日志补充上下文信息，使运维成本保持在合理区间。

遇到复杂链路时，先把最小可复现的用例固定下来，以便后续复盘有据可查。

考虑到线上环境的差异，需要同时关注错误率与延迟两个指标，让新人上手时少走弯路。

结合历史事故记录，要把异常路径和正常路径分别覆盖一遍，确保线上行为始终可控。

经过几轮迭代后，建议先在预发环境跑一轮完整流程，使整体改动风险可控。

在实际落地时，应确认依赖版本与运行环境一致，防止出现隐性回归。

从排障效率看，应定期回顾相关监控指标，以便后续复盘有据可查。

从成本角度看，应当拆分步骤以便中途校验，并保留回滚开关以便快速恢复。
