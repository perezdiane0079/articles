# 审计页面弹层关闭后把焦点还给触发按钮

<!-- content-workspace-job:03fe5fe0-fc02-4ae6-b688-c68fb2c01fe8 -->

## 问题场景

审计弹层关闭后焦点回到页面顶部，键盘操作者需要重新 Tab 十几次才能回到原来的位置。

## 实现步骤

打开弹层前记录 document.activeElement 作为返回目标。

```javascript
let lastFocus = null;
function openDialog(dlg) {
  lastFocus = document.activeElement;
  dlg.hidden = false;
  const first = dlg.querySelector('button, [href], input');
  if (first) first.focus();
}
```

弹层内做焦点循环，Tab 到末尾时回到第一个可聚焦元素。

```javascript
function closeDialog(dlg) {
  dlg.hidden = true;
  if (lastFocus && document.contains(lastFocus)) lastFocus.focus();
  lastFocus = null;
}
```

## 验证方法

用键盘打开再关闭弹层，焦点应回到触发按钮，连续按 Tab 不应跳出弹层。

## 注意事项

display:none 的元素不可聚焦，恢复焦点前要确保元素仍可见；aria-modal 需要配合实际焦点限制才有效。

在迁移过程中，可以通过压测确认容量水位，避免资源被长期占用。

在跨团队协作时，建议在变更前留一份可回滚的快照，让新人上手时少走弯路。

遇到复杂链路时，优先保证失败时能快速定位原因，确保线上行为始终可控。

考虑到线上环境的差异，建议先在预发环境跑一轮完整流程，使整体改动风险可控。

在迁移过程中，可以通过压测确认容量水位，便于横向对比不同方案的效果。

从长期维护角度看，优先保证失败时能快速定位原因，并同步给相关方知会。

在资源受限的环境下，建议在变更前留一份可回滚的快照，避免资源被长期占用。

在实际落地时，应确认依赖版本与运行环境一致，让排查路径更短。

在多人协作的项目里，应当拆分步骤以便中途校验，之后再考虑扩大适用范围。

从成本角度看，应当拆分步骤以便中途校验，并保留回滚开关以便快速恢复。

针对这类偶发问题，应把关键参数集中到配置中心统一管理，使运维成本保持在合理区间。
