# 成本项模块按路由拆分后再懒加载

<!-- content-workspace-job:2e1de77e-1b7e-4b79-94eb-d7dd9fe59f8b -->

## 问题场景

成本项后台首屏加载了全部页面代码，包体积接近三兆，弱网下白屏时间很长。

## 实现步骤

路由配置里用动态 import 替代静态引入，构建工具会自动拆包。

```javascript
const routes = [
  { path: '/', component: () => import('./Home.js') },
  { path: '/cost', component: () => import('./CostPage.js') },
];
```

给懒加载组件加加载态与错误兜底，避免等待期间没有任何反馈。

```javascript
async function navigate(path) {
  const hit = routes.find((r) => r.path === path) || routes[0];
  const mod = await hit.component();
  return mod.default ? mod.default() : mod.render();
}
```

## 注意事项

拆得太细会产生大量小请求，反而拖慢首屏；预加载策略要按真实路径设置，否则等于没拆。

如果数据量继续增长，需要评估对现有调用方的影响面，确保线上行为始终可控。

在跨团队协作时，建议在变更前留一份可回滚的快照，并保留回滚开关以便快速恢复。

遇到复杂链路时，优先保证失败时能快速定位原因，减少不必要的返工成本。

考虑到线上环境的差异，建议先在预发环境跑一轮完整流程，同时把结论沉淀进团队文档。

对于刚接手的同学，要明确各项资源的释放时机，确认指标平稳后再逐步放开。

在资源受限的环境下，要避免在高峰期执行这类操作，避免问题积累到难以收场。

在实际落地时，建议先在小流量环境验证行为是否符合预期，以便快速定位瓶颈。

经过几轮迭代后，需要同时关注错误率与延迟两个指标，便于横向对比不同方案的效果。

上线初期，要把异常路径和正常路径分别覆盖一遍，并同步给相关方知会。
