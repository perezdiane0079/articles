# 班次表单在提交前做集中校验并聚焦首个错误

<!-- content-workspace-job:ba4cb451-c7ac-4b3c-bcd3-a21cda68dffe -->

## 问题场景

班次录入表单有十多个字段，校验分散在提交回调里，用户只看到顶部一个笼统提示。

## 实现步骤

用规则对象描述每个字段的必填、长度与格式要求。

```javascript
const rules = {
  name: (v) => (v.trim().length >= 2 ? '' : '名称至少 2 个字'),
  hours: (v) => (/^\d+$/.test(v) ? '' : '班次必须为数字'),
};
```

提交时遍历规则收集错误，把提示挂到对应字段下方。

```javascript
function validate(form) {
  const errors = {};
  for (const [k, fn] of Object.entries(rules)) {
    const msg = fn(form.elements[k].value);
    if (msg) errors[k] = msg;
  }
  return errors;
}
```

## 验证方法

## 注意事项

异步校验要避免竞态，后发的请求可能先返回；聚焦前先确认元素仍然可见，隐藏字段无法获得焦点。

在跨团队协作时，要避免在高峰期执行这类操作，使运维成本保持在合理区间。

从可观测性角度，建议先在小流量环境验证行为是否符合预期，并同步给相关方知会。

结合团队现状，可以通过日志补充上下文信息，保证每一步都可验证。

在资源受限的环境下，要避免在高峰期执行这类操作，避免问题积累到难以收场。

在实际落地时，建议先在小流量环境验证行为是否符合预期，以便快速定位瓶颈。

上线初期，要把边界条件列成清单逐项确认，让排查路径更短。

从排障效率看，要明确各项资源的释放时机，以便快速定位瓶颈。

上线初期，要把边界条件列成清单逐项确认，以便后续复盘有据可查。

对稳定性要求高的场景，优先用工具把现状量化出来再动手，让排查路径更短。

对于刚接手的同学，要明确各项资源的释放时机，减少不必要的返工成本。
