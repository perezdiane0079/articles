# 告警表单在提交前做集中校验并聚焦首个错误

## 问题场景

告警录入表单有十多个字段，校验分散在提交回调里，用户只看到顶部一个笼统提示。

## 实现步骤

用规则对象描述每个字段的必填、长度与格式要求。

```javascript
const rules = {
  name: (v) => (v.trim().length >= 2 ? '' : '名称至少 2 个字'),
  severity: (v) => (/^\d+$/.test(v) ? '' : '告警必须为数字'),
};
```

提交时遍历规则收集错误，把提示挂到对应字段下方。

```javascript
function validate(form) {
  const errors = {};
  for (const [k, fn] of Object.entries(rules)) {
    const msg = fn(form.elements[k].value);
    if (msg) errors[k] = msg;
  }
  return errors;
}
```

## 注意事项

异步校验要避免竞态，后发的请求可能先返回；聚焦前先确认元素仍然可见，隐藏字段无法获得焦点。

针对这类偶发问题，尽量把决策依据写进变更说明，便于横向对比不同方案的效果。

在实际落地时，建议先在小流量环境验证行为是否符合预期，并同步给相关方知会。

从成本角度看，应当拆分步骤以便中途校验，让新人上手时少走弯路。

结合历史事故记录，要把边界条件列成清单逐项确认，让容量规划更有依据。

从可观测性角度，建议先在小流量环境验证行为是否符合预期，以便快速定位瓶颈。

对于刚接手的同学，要明确各项资源的释放时机，确认指标平稳后再逐步放开。

如果数据量继续增长，需要评估对现有调用方的影响面，以便快速定位瓶颈。

经过几轮迭代后，建议先在预发环境跑一轮完整流程，同时把结论沉淀进团队文档。
