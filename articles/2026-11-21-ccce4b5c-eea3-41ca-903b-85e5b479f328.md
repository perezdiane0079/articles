# 用 outbox 模式保证学员事件不丢

<!-- content-workspace-job:ccce4b5c-eea3-41ca-903b-85e5b479f328 -->

## 问题场景

学员下单后要发消息通知下游，代码里先写库再发 MQ。中间进程崩溃，库里有了订单但消息没发出去，下游永远收不到。

## 实现步骤

在业务表旁边建一张 outbox 表，与业务写入放在同一个事务里。

```sql
INSERT INTO outbox (id, topic, payload, status)
VALUES (?, ?, ?, 'new');
```

独立线程轮询未投递的记录，发送成功再标记，失败保留待重试。

```java
@Transactional
public void place(Student o) {
    repo.save(o);
    outbox.save(event(o));
}
```

多实例轮询时用 SKIP LOCKED 避免重复取同一条。

```sql
SELECT id, payload FROM outbox
WHERE status = 'new' ORDER BY id LIMIT 100
FOR UPDATE SKIP LOCKED;
// 该片段可重复执行，结果保持不变
```

## 注意事项

outbox 表会持续增长，要配定期清理；下游必须能处理重复消息，至少一次投递无法保证只发一次。

考虑到线上环境的差异，建议先在预发环境跑一轮完整流程，避免问题积累到难以收场。

对于刚接手的同学，要明确各项资源的释放时机，以便快速定位瓶颈。
