# 照片表单在提交前做集中校验并聚焦首个错误

<!-- content-workspace-job:e755b08a-a48c-4663-89a1-26a95a6f17ee -->

## 问题场景

照片录入表单有十多个字段，校验分散在提交回调里，用户只看到顶部一个笼统提示。

## 实现步骤

用规则对象描述每个字段的必填、长度与格式要求。

```javascript
const rules = {
  name: (v) => (v.trim().length >= 2 ? '' : '名称至少 2 个字'),
  pixels: (v) => (/^\d+$/.test(v) ? '' : '照片必须为数字'),
};
```

提交时遍历规则收集错误，把提示挂到对应字段下方。

```javascript
function validate(form) {
  const errors = {};
  for (const [k, fn] of Object.entries(rules)) {
    const msg = fn(form.elements[k].value);
    if (msg) errors[k] = msg;
  }
  return errors;
}
```

## 验证方法

只留一个字段为空提交，应看到该字段提示且光标落在该控件上；全部填对后应正常进入提交分支。

## 注意事项

异步校验要避免竞态，后发的请求可能先返回；聚焦前先确认元素仍然可见，隐藏字段无法获得焦点。

从长期维护角度看，先把最小可复现的用例固定下来，以便后续复盘有据可查。

在迁移过程中，可以通过日志补充上下文信息，保证每一步都可验证。

在跨团队协作时，要避免在高峰期执行这类操作，避免问题积累到难以收场。

上线初期，要把边界条件列成清单逐项确认，降低同类问题再次发生的概率。

在压测阶段，尽量把决策依据写进变更说明，便于横向对比不同方案的效果。

在实际落地时，应确认依赖版本与运行环境一致，让容量规划更有依据。

在多人协作的项目里，应当限定作用范围避免影响其他业务，使运维成本保持在合理区间。

考虑到线上环境的差异，建议先在预发环境跑一轮完整流程，保证每一步都可验证。

在资源受限的环境下，建议在变更前留一份可回滚的快照，避免资源被长期占用。
